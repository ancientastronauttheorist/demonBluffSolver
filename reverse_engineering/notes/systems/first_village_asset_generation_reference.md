# Independent first-village asset generation reference

This is an authored conditional reference, separate from the frozen original setup,
acquisition and Hunter probes. It models the conditional original N5 profile
21674 through **BEFORE_FIRST_INIT**, followed by separately supplied ordinary
Minion selector calls. No native instructions, solver transitions, role callback
simulation, public-world construction, probabilities or weights are imported.

The authored implementation is
[reference_first_village_asset_generation.py](../../scripts/reference_first_village_asset_generation.py).
It uses only the Python standard library. Its algorithm accepts original parsed
asset inputs and recorded choices; it never reads generation-report outcomes to
construct an expected path. A separate JSON-only comparison reader has compared
recorded factors under their actual conditioning. Those comparisons do not turn
the reference into a native execution certificate or a complete joint model.
The reviewed reference source SHA256 is
`deaaad9bfaa3b3378f479a852bedaf8f4f6c56ff4a2416e60a2d948236f48547`.

## Independent transition contract

The laws were authored from operand and caller audits, rather than Rust replay
or generation outcomes. Relevant evidence is
[first-village profile generation](first_village_profile_generation.md),
[pool composition](manage_pool_composition.md),
[unique source composition](unique_source_composition.md),
[round candidate composition](round_candidate_composition.md), and
[ascension asset graph](ascension_asset_graph.md). The native-generation factor
report is comparison-only; no expected-state construction imports it.

The explicit supplied fixture contract initializes distinct current and saved
roster lists empty at version 0, three pools empty at version 0, array versions
absent, valid runtime headers/generic metadata, stable collection providers,
sufficient capacity, inert positions service and field-faithful distinct profile
copies. These runtime list identities and versions come from the fixture/service
contract, not serialized asset initialization or a game-start certificate.

Inline script rosters are version-0 **lists**. The original stored starting
fields are separate **arrays**, with independently sourced serialized field
origins. A selected script field-copy has distinct lists whose placement links
point to inline sources. Before starting materialization, the supplied shallow
profile copy shares the original stored arrays; materialization replaces its
working starting fields with new arrays sourced from those selected lists. The
reference exposes that source/copy topology as a constructor/materialization
contract, and preserves the original stored array unchanged. Sparse recorded
contents do not expose those raw pointer aliases, so no cross-case native alias
equality or all-distinct raw object certificate is claimed.

1. Standard selection samples the singleton Minion and four Villagers from the
   original five, removing the **first asset-equal** local occurrence after each
   Add. Current roster order is preserved. It does not clear current rosters in
   this fresh-empty domain. Current versions become `[4,0,1,0]` under the declared
   Add contract. Saved rosters remain empty at version 0.
2. GetRandom separately samples local copies of current Minion and Villager
   lists. Every sampled asset is already current, so its conditional current
   Add is suppressed in this domain. Ten integer choice widths are
   `[1,5,4,3,2,1,4,3,2,1]`. Its source order is distinct from current roster order.
3. One supplied finite float32 key is bound to each returned source occurrence.
   Stable ascending order uses source index to resolve equal keys, preserving
   exact bits including signed zero. NaN, infinity and values outside `[0,1]`
   are unsupported. Finite supplied key plans do not establish Unity RNG
   reachability or likelihood. The materialized return list is distinct and
   version 0; sorted order determines actor occurrence and descending display ID.
4. Unique setup captures typed starting order Demons/Outsiders/Minions/Villagers
   and a distinct current-script snapshot Villagers/Outsiders/Minions/Demons
   before clearing its pool. A supplied deferred RemoveAll deletes every
   starting occurrence whose asset occurs in the captured script. Direct
   candidates require bluffable and real type Villager or Outcast; they do not
   require Good alignment. Each Add precedes first-equal local removal.
5. When unique count is at most one, fallback concatenates actual serialized
   profile townsfolks/outsiders/minions/townsfolks (`0x68/0x70/0x78/0x68` in
   Gameplay.GetAllAscensionCharacters `0x37C1A0`). It preserves 63 source
   placements and filters bluffable, Good 10, real Villager 10 to 48 eligible
   occurrences/24 assets. It does not exclude current script members again and
   does not remove the selected fallback occurrence. No Resources catalogue
   order is substituted. Profile graph rereads have no intervening writers.
6. Duplicate setup captures a second distinct current-script list before
   clearing its own pool. Bluffable Villager/Outcast filters drive selection;
   the allocated Good-filter output is discarded, rather than narrowing the
   Villager candidates. Each selected local asset is removed first-equal after
   Add. The N5 pool choice widths are `[1,48,4,3,2,1]`; final unique/duplicate/
   must-include versions are `[3,5,0]`. An empty initial Villager candidate list
   still reaches the unguarded zero-width draw/index failure contract.
7. The finite exit identifies actor occurrence 0, sorted return occurrence 0,
   display ID 5 **before any Character.Init body**. Every original actor has
   qualified pending rows joining its occurrence, data occurrence, asset key,
   managed class/TypeDefIndex and triggers Init 3 / AfterRoundStart 7. Method

   selected copied role gains the same qualified pending rows for its actor.

The reference models the successful stable collection/allocator/filter/sort
contract. It does not implement arbitrary service failure rollback, CLR unwind,
native write-barrier failure prefixes or temporal replacement callbacks. It
retains missing/invalid choices, unsupported inputs and capacity boundaries as
distinct output statuses, with available prefix state; it never silently prunes
or renormalizes them.

## Saved API and output schema

`asset_generation_input_v0` contains the raw profile, typed assets, input pins,
domain, explicit `fixture_contract`, origin and immutable seal.

`run_generation_case(inputs, plan)` consumes `generation_indices`,
`float_key_bits`, `pool_indices` and optional positive `collection_capacity`.
It emits `asset_generation_reference_v0` with `status`, `reason`, `detail`,
`generation_stage`, `before_first_init` and `prefix_state`. Each stage exposes:

- `assets` keyed by `file_id:path_id`, and `occurrences` keyed by occurrence ID.
- `lists` keyed by logical identity, with kind, occurrence items, version and
  version provenance; current/saved/source/selected-copy/temporary roster maps
  and an availability-qualified source/copy topology ledger.
- working cache and count identities/fields, source-linked top-level temporary
  count labels, returned source/sorted occurrences, raw key bits and ordinals.
- fallback source/eligible placements, ordered pools, physical board assignments,
  recorded draw traces, first-equal removal traces and pending obligations.

Current-list versions and saved-list identities are authored source/provider
effects; the existing factor corpus does not expose them for comparison. Its
per-method diagnostic `returned_list` marker is reset for pool/selector calls;
the reference instead preserves the persistent return collection. Neither
difference is normalized into a measured native claim. Intermediate scratch
allocations are logical model evidence, not raw native-memory equality.

`run_minion_selector(inputs, before_first_init, die, index, invocation_contract)`
is separately conditioned on the actual sorted ordinary Minion actor occurrence
and unchanged pools. Die range is `[1,11)`: 1-4 selects duplicate with no
registration attempt; 5-10 selects unique and attempts exact-asset membership
registration. Neither selector consumes its pool. A new selected asset appends
only to its actual faction current roster and increments that list version;
an existing asset suppresses the Add. Outputs distinguish `registered` from
`registration_attempted`, branch, source index, selected occurrence and final
state. This is not a native original Minion Init/copy history.
`selected_copy_obligations` joins the selected pool occurrence and typed asset
to the invocation actor; it records pending, unresolved Init and AfterRoundStart
obligations rather than executing a copied role.

`enumerate_generation_cases` takes explicit finite key plans and case capacity;
it enumerates recorded integer history products with an explicit capacity or
domain-exhausted boundary row. `derived_choice_widths` computes fallback eligible
width from supplied profile PPtrs and character input eligibility, instead of
hard-coding 48 for direct synthetic API inputs. The remaining finite N5
derivation requires five distinct bluffable real Villager starting assets and
one real Minion; unsupported derivations and empty fallback domains produce an
explicit unsupported enumeration boundary. Invalid supplied float-key plans
also retain an explicit boundary rather than disappearing from the domain.
`enumerate_minion_selectors` does the same for a
separately conditioned state. Neither API attaches weights. Actual full mixed
callback closure, public observations/history, solver worlds and policy remain
outside this reference. Known six original callbacks do not close other eligible
fallback assets' initialization or public clues.
